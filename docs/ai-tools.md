# AI ツールと apm

## 目的

AI ツールの共通設定とスキルの依存関係を一元管理し、ツールごとの展開先を手作業で同期する手間を省きます。

## 管理範囲

| 対象                   | 管理場所                                | 反映先                                        |
| ---------------------- | --------------------------------------- | --------------------------------------------- |
| 共通のエージェント指示 | `dotfiles/ai/instructions/AGENTS.md`    | `~/.codex/AGENTS.md` と `~/.claude/CLAUDE.md` |
| Claude Code の実行許可 | `dotfiles/ai/claude/settings.json`      | `~/.claude/settings.json`                     |
| Codex の実行許可       | `dotfiles/ai/codex/rules/default.rules` | `~/.codex/rules/default.rules`                |
| apm の依存関係         | `dotfiles/ai/apm/apm.yml`               | `~/.apm/apm.yml`                              |
| apm の設定             | `dotfiles/ai/apm/config.json`           | `~/.apm/config.json`                          |
| apm の解決結果         | `dotfiles/ai/apm/apm.lock.yaml`         | `~/.apm/apm.lock.yaml`                        |

`AGENTS-ja.md` は共通指示の日本語版として管理しますが、各エージェントの設定ディレクトリにはリンクしません。実行許可の形式はツールごとに異なるため、共通形式へ無理に変換せず、ツール固有の設定ファイルをそのまま管理します。

## apm の配備

`apm.yml` と `config.json` は、mise の `symlink-each` を利用して `~/.apm` 配下へリンクします。一方、apm コマンドによって自動更新される `apm.lock.yaml` は `copy` で配備し、更新後にリポジトリの管理元へ書き戻します。

`~/.apm` は通常のディレクトリとして扱い、`apm_modules/` などの生成物はリポジトリに含めません。スキルの展開結果は `apm.lock.yaml` の `deployed_files` を基準に確認します。

初回セットアップ時は、`mise bootstrap` が lock ファイルの記述に従ってユーザー単位のスキルを反映します。

依存関係を更新する際は、リポジトリの更新タスクを実行します。このタスクにより、apm の更新結果が `dotfiles/ai/apm/apm.lock.yaml` へ自動で書き戻されます。

```sh
mise run --continue-on-error upgrade
```

更新された lock ファイルは手作業で直接編集せず、他の依存関係更新と同様に差分を確認した上でコミットします。

## スキルの置き場所

スキルの利用範囲に合わせて管理場所を適切に選択します。

| 利用範囲                               | 管理場所                                                     |
| -------------------------------------- | ------------------------------------------------------------ |
| 公開可能で、複数リポジトリで再利用する | 公開 apm パッケージ                                          |
| 非公開とし、複数リポジトリで再利用する | プライベートリポジトリの apm パッケージ                      |
| 特定リポジトリの文脈にのみ依存する     | 当該リポジトリのプロジェクト単位の apm 管理                  |
| dotfiles のユーザー環境で共通利用する  | `dotfiles/ai/apm/apm.yml` から参照するユーザー単位の依存関係 |
| 一度限りの作業で再利用しない           | ユーザーのプロンプト                                         |

本リポジトリは公開リポジトリであるため、`apm.yml` から参照する依存関係は公開可能なものに限定します。スキル本体は原則として外部の apm パッケージ側で管理し、dotfiles 側には依存関係定義と lock ファイルのみを配置します。

`.agents/skills` や `.claude/skills` など、apm の展開先ディレクトリを直接編集してはいけません。プロジェクト固有のスキルは、当該リポジトリの `.apm/skills` または依存先のパッケージリポジトリで編集します。

## 説明を置く場所

- 作業全体で参照する設計原則や規約は、`AGENTS.md` または `docs/` に記述する
- 特定の作業でのみ必要な手順は、利用範囲に応じたスキル内に記述する
- 長大な補足資料は、必要時にのみ参照するスキルの `references/` または `docs/` に配置する
- `AGENTS.md` には詳細を重複して記述せず、参照先や作業領域ごとの案内のみを残す

## 依存関係を変更する手順

1. スキルの利用範囲を決め、管理場所を選択する
2. スキルを配置した apm パッケージまたはプロジェクト側で変更を加える
3. 参照側の `apm.yml` を更新する
4. ユーザー単位であれば dotfiles の更新タスクを、プロジェクト単位であれば `apm update` を実行する
5. lock ファイルの差分、コンテンツハッシュ、展開先ファイルを確認する
6. 対象の AI ツールからスキルを実行し、正常に動作することを確認する

認証トークンやマシン固有の値をコミットに含めてはいけません。また、公開 dotfiles リポジトリからプライベートな依存関係を参照しないようにしてください。

## 現在の制約

- ユーザー単位のインストールでは、apm が出力する `.agents/skills` と `.claude/skills` を利用する
- Codex や GitHub Copilot では、`.agents/skills` を読み込む環境でスキルを利用する
- `.codex/skills` や `.copilot/skills` への個別展開は管理対象外とする
- `apm.yml` の依存関係はバージョンを固定していないため、更新時は必ず lock ファイルの差分を確認する
