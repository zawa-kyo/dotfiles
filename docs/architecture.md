# アーキテクチャ

## 目的

このリポジトリは、日常的に使うローカル開発環境を別のマシンでも再現するための dotfiles 集です。設定ファイル、セットアップ、CLI、タスク、AI ツールの設定をまとめて管理します。

## 文書の役割

- `README.md`
  - 人向けのセットアップと日常運用
- `AGENTS.md`
  - エージェント向けの参照先
- `docs/README.md`
  - リポジトリ全体と各サブシステムの文書へ進むための目次
- リポジトリ直下の `docs/`
  - リポジトリ全体の設計判断
- 各サブシステムの `docs/`
  - 実装に近い設計と運用の文書

エージェントは `AGENTS.md` から `docs/README.md` へ進み、目次から対象の文書を選びます。サブシステムに固有の文書は、そのサブシステムの `docs/README.md` を目次として参照します。

## 主要ディレクトリ

- `dotfiles/`
  - mise でホームディレクトリへリンクする設定
  - `ai/`、`editors/`、`shell/`、`terminal-apps/`、`tools/` に分ける
- `bin/`
  - `~/.local/bin` へ公開する単独実行コマンド
- `libexec/`
  - 公開コマンドから共有する非公開の補助処理
- `setup/`
  - 環境構築に使う Homebrew と Bun の宣言およびスクリプト
  - `migrations/` には、現在の宣言だけでは扱えないデータ移行を置く
- `.mise/tasks/`
  - mise から実行するリポジトリ管理タスク
  - 短いタスクと実行関係は目的別の TOML ファイル、複数行のシェル処理は file task に置く
- `tests/`
  - 一時的なホームディレクトリと実際の mise を使う Go の結合テスト

`node_modules/` や `apm_modules/` などの生成状態はリポジトリに置きません。Bun は `~/.bun/install/global`、apm は `~/.apm` に生成します。

## 設計原則

### 対象ごとにまとめる

設定を探すときに配備先をたどらなくて済むよう、同じ対象のファイルをまとめます。たとえば、Neovim は `dotfiles/editors/nvim/`、Zsh は `dotfiles/shell/terminal/` に置きます。Bun のセットアップに使うファイルは `setup/bun/` に置き、ホームディレクトリへリンクする設定と区別します。

ホームディレクトリや macOS の `Library/` との対応は、`mise.toml` と `mise.macos.toml` の `[dotfiles]` で明示します。配備先を配置だけから推測できることより、関連する設定を一か所で変更できることを優先します。

### リンク設定とセットアップ処理を分ける

- 通常のリンクは mise の `[dotfiles]` に宣言する
- OS 固有の宣言は OS 別の mise 設定へ分ける
- OS 固有のツールと環境変数は、mise の `os` 制約または OS 別設定へ分ける
- 既存のファイルを残したいディレクトリでは `symlink-each` を使う
- Homebrew と Bun の宣言や導入処理は `setup/` に置く
- 現在の宣言だけでは扱えないデータ移行を `setup/migrations/` に置く

mise とは別の配備一覧や、リンクの作成元を記録するファイルは持ちません。通常の配備は mise に任せ、このリポジトリのコードは必要なデータ移行に絞ります。詳しくは [mise bootstrap 設計](./bootstrap-design.md)を参照してください。

### ツールが期待する場所を変えない

`mise.toml`、`mise.lock`、`hk.pkl`、`go.mod` など、各ツールがルートから読み込むファイルは移動しません。mise のタスク定義は、標準の探索先である `.mise/tasks/` に置きます。ルートのファイル数を減らすためだけに独自の設定用ディレクトリへ移し、実行時の追加オプションを増やすことは避けます。

### 公開コマンドと内部処理を分ける

- 初回セットアップには `mise bootstrap` を使う
- `mise run install` も同じセットアップ処理を呼ぶ
- 日常利用する CLI は `bin/` から `~/.local/bin` へ公開する
- 親シェルを変更する操作だけをシェル関数に残す
- 複数の用途で共有する補助処理は、必要になった時点で `libexec/` 直下に抽出する
- 特定の用途に閉じた内部処理は、`libexec/` の用途別ディレクトリか呼び出し元の近くに置く

### 個別のルールは実装の近くに置く

複数のサブシステムで共有する原則は `docs/` に置き、各サブシステムに固有の規則は実装の近くに置きます。たとえば、省略入力に共通する文法は `docs/abbreviation.md`、Neovim のキーバインドや表示方針は `dotfiles/editors/nvim/docs/` で管理します。各文書は共通部分を複製せず、関連する文書を相互に参照します。

### 生成物と利用者データを追跡しない

宣言ファイルと lock ファイルはリポジトリで管理し、インストール結果やキャッシュはホームディレクトリ側へ置きます。移行処理では、このリポジトリが作成したと確認できるファイルやリンクだけを変更します。
