# コマンドとタスクの設計

## 目的

日常的に使うコマンドを実行方式ごとに整理し、1 つの操作に複数の正式な入口を持たせないようにします。

## 実行経路

### 単独実行コマンド

- 実装は `bin/` に置く
- mise の `symlink-each` で `~/.local/bin` へ同名のまま公開する
- 利用時は mise タスクを経由せず直接実行できる
- ファイル名に `.sh` などの拡張子を付けず、公開名と一致させる
- 実装言語は shebang で示し、将来実装を置き換えても公開名を変えない

たとえば、次のコマンドです。

- `reveal-repository-with-neovim`
- `switch-branch`
- `switch-branch-remote`
- `search-task`

### `mise bootstrap`

- dotfiles の反映と、初回セットアップに必要な後続タスクの入口
- `mise.toml` と OS 別設定の宣言に基づいて実行する
- 定常的なリンク処理を独自スクリプトで再実装しない

### `mise run`

- 整形、検証、依存関係の更新など、リポジトリ運用の入口
- `mise tasks` で発見できることに価値がある処理を対象にする
- `mise run install` は `mise bootstrap` の互換入口としてのみ残す

### シェル関数

- 現在のシェルセッションを直接変更する操作だけを残す
- 外部プロセスにするとカレントディレクトリなどの変更が失われる場合に使う

たとえば、次の関数です。

- `reveal-repository`
- `reveal-repository-with-zoxide`
- `search-theme`

## 設計原則

### 単独実行コマンド

- 日常利用する CLI は単独実行コマンドを優先する
- PATH と mise タスクの両方へ同じ操作を公開しない
- `bin/` の隣接ファイルを利用者が追加しても、`symlink-each` の適用で削除しない
- ShellCheck と shfmt は拡張子ではなく `bin/*` も対象にする
- `.sh` は `libexec/` や `setup/` に置く内部実装で使い、公開コマンドには付けない

### `fzf` の利用

- `bin/` または `tasks/` で `fzf` を使う場合は、原則として `libexec/fzf.sh` を経由する
- `--preview` の有無にかかわらず、素の `fzf` を直接呼ばない
- 候補生成、`--bind`、`--delimiter` などのコマンド固有ロジックは呼び出し側に残す
- preview を別シェルで動かす場合だけ、ラッパーの上書き手段を明示する

### mise

- セットアップ、整形、検証、アップグレードの入口に使う
- 短い直接操作をすべて `mise run` で包まない
- dotfiles の状態確認や反映には `mise bootstrap dotfiles` の標準操作を使う

### シェル関数

- カレントディレクトリ変更など、親シェルを変える必要がある操作だけを残す
- 単にツールを起動するだけのものは単独実行コマンドに寄せる

## コマンドの公開

`bin/` に実行可能なファイルを追加すると、次回の `mise bootstrap dotfiles apply` で `~/.local/bin` にリンクされます。削除したコマンドのリンクも削除する場合は、宣言を変える前に `mise bootstrap dotfiles unapply` の対象を確認します。mise は管理台帳を持たないため、宣言から先に消した項目を後から自動判定して掃除する設計にはしません。

## 変更時の判断基準

- 新しい CLI を追加する
  - まず単独実行コマンドで成立するかを考える
- mise タスクを追加する
  - リポジトリ運用や一覧性に価値があるかを見る
- シェル関数を追加する
  - 親シェルを変える必要があるかを確認する
