# コマンドとタスクの設計

## 目的

このリポジトリでは、日常的に使うコマンドを実行方式ごとに整理し、責務を混ぜないことを目指します。

## 3つの実行経路

### 単独実行コマンド

- 管理する場所は `bin/`
- `~/.local/bin` に公開される
- `mise` に依存せず直接実行できる

例を示す。

- `reveal-repository-with-neovim`
- `switch-branch`
- `switch-branch-remote`
- `search-task`

### `mise run`

- タスクの入口と一覧
- インストール、整形、チェック、アップグレードのようなリポジトリ運用の導線

### シェル関数

- 現在のシェルセッションを直接変更する必要があるものはシェル関数に残す
- 外部プロセス化すると意味が壊れるものを対象にする

例を示す。

- `reveal-repository`
- `reveal-repository-with-zoxide`
- `search-theme`

## 設計原則

### 単独実行コマンドの原則

- 日常利用する CLI は単独実行コマンドを優先する
- 実装は `bin/` に置く
- PATH と `mise` タスクの両方へ同じコマンドを公開しない

### `fzf` 利用の原則

- `bin/` または `tasks/` で `fzf` を使う場合は、原則として `libexec/fzf.sh` のラッパー経由にする
- `--preview` の有無にかかわらず、素の `fzf` を直接呼ばない
- 候補生成、`--bind`, `--delimiter` などのコマンド固有ロジックは呼び出し側に残す
- `preview` を別シェルで動かしたい場合だけ、ラッパーの上書き手段を使って明示する

### `mise` の原則

- リポジトリのセットアップ、整形、検証、アップグレードの入口に使う
- タスクの一覧として使う
- 直接の最短操作をすべて `mise run` に寄せない

### シェル関数の原則

- カレントディレクトリ変更など、親シェルを変える必要がある操作だけを残す
- 単にツールを起動するだけのものは単独実行コマンドに寄せる

## ディレクトリ分割

- `tasks/`
  - セットアップ、インストール、同期のようなリポジトリ内ローカル処理
- `bin/`
  - 公開する単独実行コマンド
- `libexec/`
  - 共通補助スクリプト

## 公開フロー

通常の公開経路は次です。

1. `bin/` にコマンドを置く
2. `tasks/sync-global-commands.sh` で `~/.local/bin` にリンクする

同期処理は、旧構成で生成したグローバル `mise` ラッパーも削除する。管理元を確認できないタスクは変更しない。

## 変更時の判断基準

- 新しい CLI を追加する
  - まず単独実行コマンドで成立するかを考える
- `mise` タスクを追加する
  - リポジトリ運用や一覧性に価値があるかを見る
- シェル関数を追加する
  - 親シェルを変える必要があるかを確認する
