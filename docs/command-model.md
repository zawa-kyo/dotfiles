# コマンドとタスクの設計

## 目的

日常的に使用するコマンドの実行方式を体系的に整理し、同一の操作を複数の経路で重複して公開しないように設計します。

## コマンドの使い分け

### 単独実行コマンド

- 実装は `bin/` 配下に配置する
- mise の `symlink-each` により、`~/.local/bin` へ同名でシンボリックリンクを公開する
- 利用時は mise タスクを経由せず、シェルから直接呼び出せる
- スクリプトファイル名に `.sh` などの拡張子を付けず、公開コマンド名と一致させる
- 実装言語は shebang で指定し、将来的に実装言語を置き換えても公開名を変更しない

`bin/` 配下の主な公開コマンドは次のとおりです。

| コマンド                         | 用途                                                       |
| -------------------------------- | ---------------------------------------------------------- |
| `reveal-process`                 | プロセス一覧を `fzf` で検索・確認する                      |
| `reveal-process-cpu`             | CPU 使用率順にソートしてプロセス一覧を表示する             |
| `reveal-process-memory`          | メモリ使用量順にソートしてプロセス一覧を表示する           |
| `reveal-repository-with-browser` | リポジトリの Web ページをブラウザで開く                    |
| `reveal-repository-with-code`    | リポジトリを VS Code で開く                                |
| `reveal-repository-with-fork`    | リポジトリを Fork で開く                                   |
| `reveal-repository-with-lazygit` | リポジトリで Lazygit を起動する                            |
| `reveal-repository-with-neovim`  | リポジトリを Neovim で開く                                 |
| `search-abbreviation`            | シェルの省略コマンド定義を検索・確認する                   |
| `search-bookmarks`               | ブラウザのブックマークを横断検索する                       |
| `search-bookmarks-chrome`        | Google Chrome のブックマークを検索する                     |
| `search-bookmarks-safari`        | Safari のブックマークを検索する                            |

### `mise bootstrap`

- dotfiles のリンクを反映し、初回セットアップに必要な準備タスクを実行する
- `mise.toml` および OS 別設定の宣言に基づいて実行する
- 通常のリンク作成処理をシェルスクリプトなどで独自に再実装しない

### `mise run`

- コード整形、静的検査、依存関係の更新など、リポジトリの管理・保守に使用する
- `mise tasks` で一覧表示・検索できることに価値がある処理を対象とする
- `mise run install` は `mise bootstrap` と同一処理を呼び出す互換エイリアスとする

### シェル関数

- カレントディレクトリの移動など、現在のシェルセッションの状態を直接変更する必要がある操作のみを残す
- 外部プロセスとして実行するとプロセスの終了と同時に変更が失われてしまう処理に限定する

たとえば、次の関数が該当します。

- `reveal-repository`
- `reveal-repository-with-zoxide`
- `search-theme`

## 設計原則

### 単独実行コマンド

- 日常的に利用する CLI は、単独実行コマンドとしての提供を最優先とする
- 同一の操作を PATH (`~/.local/bin`) と mise タスクの双方に重複して公開しない
- ユーザーが `~/.local/bin` に他のファイルを配置していても、`symlink-each` の適用時に削除されないようにする
- ShellCheck や shfmt による検査対象には、拡張子なしの `bin/*` も含める
- `.sh` 拡張子は `libexec/` や `setup/` 配下の内部実装スクリプトにのみ使用し、公開コマンドには付けない

### `fzf` の利用

- `bin/` や `setup/` 配下で `fzf` を利用する際は、原則として `libexec/fzf.sh` のラッパーを経由する
- `--preview` の有無に関わらず、生の `fzf` を直接呼び出さない
- 候補リストの生成、`--bind`、`--delimiter` など、各コマンド固有のオプション指定は呼び出し元に残す
- プレビュー処理を別シェルで実行する場合に限り、ラッパーを上書きする手段を明示する

### mise

- セットアップ、コード整形、検証、アップグレードの統一的な入口として活用する
- 短い単発の直接実行コマンドまで無理に `mise run` でラップしない
- 環境と配備の宣言は `mise.toml`、タスク定義は `.mise/tasks/` に配置する
- 短いタスクや依存関係の定義は目的別の TOML ファイル、複数行にわたるシェルスクリプトはファイルタスクとして分離する
- dotfiles の配備状態確認、反映、解除には、`mise bootstrap dotfiles` の標準操作を用いる

### シェル関数

- ディレクトリ移動など、親シェルの環境を変更する必要がある操作のみに限定する
- 単に外部ツールを起動するだけの処理は、単独実行コマンドへ寄せる

## コマンドの公開

`bin/` に実行権限を付与したファイルを追加すると、次回の `mise bootstrap dotfiles apply` 実行時に `~/.local/bin` へ自動的にリンクされます。`symlink-each` によって作成されたリンクは mise の内部状態に記録されるため、配備元の `bin/` から削除されたコマンドのリンクは次回の適用時に自動的に削除されます。なお、`[dotfiles]` の宣言自体を削除する場合は、事前に `mise bootstrap dotfiles unapply` で対象を確認した上で解除してください。

公開コマンドから別の公開コマンドを呼び出す際も、拡張子のない公開名を使用します。ラッパースクリプトを変更した際は、呼び出し先のコマンドが `bin/` に実在することを検証します。

## 変更時の判断基準

- 新しい CLI を追加する場合:
  - まず単独実行コマンドとして成立するか検討する
- mise タスクを追加する場合:
  - リポジトリの管理・運用に資するか、タスク一覧での発見性に価値があるかを判断する
- シェル関数を追加する場合:
  - 親シェルの状態を変更する必要が本当にあるかを確認する
