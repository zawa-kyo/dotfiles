# 秘密情報の管理設計

## 目的

本ドキュメントは、dotfiles で管理する共通環境設定と、端末ごとに個別に保持すべき秘密情報 (シークレット) の分離方針および管理設計を定めたものです。
秘密情報の暗号化・管理には [fnox](https://fnox.jdx.dev/) を採用し、登録、更新、取得のインターフェースを統一します。
具体的なセットアップ手順および日常の操作コマンドは、[README](../README-ja.md) を参照してください。

## 設定の分類と役割分担

設定の共有範囲 (リポジトリ共通か端末固有か) と、秘匿性の要否 (公開可能かシークレットか) を明確に区別して管理します。端末固有の設定であっても、秘匿する必要のない値は秘密情報として扱いません。

| 種類           | 例                                 | 管理先                                     |
| -------------- | ---------------------------------- | ------------------------------------------ |
| 共通設定       | `EDITOR`、共通 PATH                | Git 管理する dotfiles                      |
| 端末固有の設定 | `EMAIL`、端末固有の PATH           | Git 管理外 (`~/local.d` など)              |
| 秘密情報       | API トークン、個人アクセストークン | Git 管理外の fnox 設定 (`~/.config/fnox/`) |

秘匿する必要のない通常設定は、シェルや各ツールから直接参照できる構成を維持します。これらを fnox に集約すると、復号鍵や fnox の起動オーバーヘッドが不要な処理にまで波及するためです。

## age の採用理由とセキュリティモデル

### 採用理由

端末ローカルの暗号化プロバイダーとして [age](https://fnox.jdx.dev/providers/age.html) を採用します。外部クラウドサービスへのログインやネットワーク接続を必要とせず、オフライン環境でも完結して動作するため、端末単位で秘密情報を自己完結させる用途に適しています。

複数端末間で秘密情報を安全に共有・同期する必要が生じた場合は、Bitwarden 等の外部プロバイダー連携を改めて検討します。

### セキュリティモデルと保護範囲

- **目的と保護範囲**: 本構成の主眼は「平文ファイルでの誤共有・漏洩防止」および「秘密情報の管理インターフェース統一」です。同一ユーザー権限で動作する悪意あるプログラムが設定ファイルと秘密鍵の両方にアクセスできる場合、値の取得を防ぐことはできません (端末全体の侵害に対する防御境界ではありません)。
- **バックアップの取り扱い**: 設定ファイル (`~/.config/fnox/config.toml`) には公開鍵・暗号文・鍵パスが記録され、秘密鍵 (`~/.config/fnox/age.txt`) がなければ復号できません。ただし、設定と秘密鍵の両方を含むバックアップからは復号可能なため、バックアップ先も厳重に保護する必要があります。また、秘密鍵を紛失すると暗号化した値は復元できません。
- **環境分離**: 私用 PC と仕事用 PC では鍵や秘密情報を共有せず、端末ごとに独立した鍵を生成・利用します。

## エイリアスの解決

同一の秘密情報がツールによって異なる環境変数名で要求される場合、暗号化する実体は 1 つにまとめ、別名は `default` の変数展開を用いて定義します。これにより、シークレット更新時の二重管理や値の不整合を防ぎます。

```toml
[secrets]
OPENAI_API_KEY = { provider = "local", value = "..." }
OPENAI_KEY = { default = "${OPENAI_API_KEY}" }
```

- **順序非依存**: シェルの初期化時に `export OPENAI_KEY="$OPENAI_API_KEY"` とする方式ではファイルの読み込み順序に依存しますが、fnox 内部で参照を解決することで、利用側が順序関係を意識する必要がなくなります。
- **エラー処理**: 参照先の secret は同一設定内で定義されている必要があります。未定義の参照や循環参照は評価時にエラーとなります。

詳細は [公式ドキュメント: default](https://fnox.jdx.dev/reference/configuration.html#default) を参照してください。

## コマンドへの受け渡し方式

常時シェル環境に秘密情報を展開することは避け、設定ファイルで `env = "exec"` を基本とします。秘密情報を必要とするコマンドは `fnox exec -- <command>` 経由で起動し、そのプロセスおよび子プロセスにのみ一時的に環境変数を注入します。

- **ログ・出力への配慮**: 起動先コマンドが受け取った環境変数をログや標準出力に記録しないか留意してください。
- **AI エージェント等での利用**: AI エージェントや自動化ツールがコマンドを実行する際も同様に `fnox exec` を経由します。ただし、エージェントに `fnox exec` の実行を許可することは秘密情報へのアクセスを許可することと同等である点に留意してください。

## bootstrap の責務

`mise bootstrap` における fnox 関連の責務は以下のとおりです。

1. **最小限の初期化**: ツール導入後に初期化スクリプト ([setup/init-fnox.sh](../setup/init-fnox.sh))を実行し、端末固有の age 鍵 (`~/.config/fnox/age.txt`) の生成と最小限の設定ファイル (`~/.config/fnox/config.toml`) の配備のみを行います。
2. **Git 管理外・非リンク**: 設定および鍵はユーザーローカル領域にのみ配置し、dotfiles のリンク配備や Git 管理の対象には含めません。
3. **非破壊原則と安全停止**: 既存の鍵や設定は上書きしません。設定ファイルが存在するにもかかわらず `age.txt` が見つからない場合は、既存の暗号文が恒久的に復号不能になるのを防ぐため、処理を中断します。
4. **登録・移行作業の手動分離**: 具体的な秘密情報の登録や、既存の平文設定 (`~/local.d` など) からの削除・移行は自動化せず、所有者が端末ごとに手動で確認しながら実施します。
