## 目的

Neovim におけるバッファ、ウィンドウ、タブをそれぞれ独立した概念として明確に区別し、画面表示やキーバインド、終了操作の意味づけを統一します。
プラグイン側で操作や表示を実装する場合も、Neovim 本来の概念定義を基準とします。

## 概念と関係

Neovim の各概念は次の意味で使用します。

| 概念       | 意味                                   |
| ---------- | -------------------------------------- |
| バッファ   | 編集対象となるメモリ上のテキスト       |
| ウィンドウ | 1 つのバッファを参照して表示する枠     |
| タブ       | 1 つ以上のウィンドウをまとめる配置単位 |

ウィンドウは必ずいずれか 1 つのタブに属し、1 つのバッファを参照して表示します。
バッファは特定のウィンドウやタブに従属せず、同一のバッファを複数のウィンドウやタブから同時に参照できます。
また、どのウィンドウからも参照されていないバッファもメモリ上に存在できます。

この文書およびキーバインド設計では、目的語として `b` をバッファ、`w` をウィンドウ、`t` をタブに割り当てます。
プラグイン固有の独自概念にこれらの略記を割り当てることはしません。

## バッファの状態

バッファの状態は、ウィンドウからの参照の有無と、本文データの読み込み状態によって決まります。

| 状態     | ウィンドウに表示 | 本文をメモリに保持 | `:ls` の表示 |
| -------- | ---------------- | ------------------ | ------------ |
| active   | あり             | あり               | `a`          |
| hidden   | なし             | あり               | `h`          |
| inactive | なし             | なし               | 空欄         |

inactive はバッファ自体が破棄された状態ではありません。
本文データはアンロード (unload) されますが、バッファ番号や設定値は保持されます。

## ウィンドウとタブを閉じたときの動作

ウィンドウやタブを閉じる操作は、バッファを削除する操作ではありません。
閉じた後も別のウィンドウで同一バッファが開かれていれば、そのバッファは active のまま維持されます。

どのウィンドウからも参照されなくなったバッファは、オプション `'hidden'` およびバッファ固有の `'bufhidden'` の設定に従って状態が遷移します。

| 条件                                              | バッファの状態           |
| ------------------------------------------------- | ------------------------ |
| `'hidden'` が有効                                 | hidden                   |
| `'hidden'` が無効で、バッファに未保存の変更がない | inactive                 |
| `'bufhidden'` に値がある                          | バッファ固有の指定を優先 |

`'hidden'` が無効で、他のウィンドウに表示されていないバッファに未保存の変更がある場合、通常の close は失敗します。
保存、強制実行、`'autowrite'` などの条件によって結果が変わるため、未保存の変更がある場合は単純に inactive には移行しません。

通常のファイルバッファでは `'hidden'` を有効にします。
これにより、ウィンドウやタブを閉じても未保存の変更や undo 履歴が維持され、表示領域のレイアウトと編集対象を独立して扱えます。
Neovim の既定値に依存せず、設定でも `hidden = true` を明記します。

一時バッファや特殊バッファの解放挙動は、各プラグインが `'bufhidden'` で指定できます。
通常のファイルバッファに対してグローバルに `unload`、`delete`、`wipe` などを指定すると変更を警告なしで失う危険があるため、全体設定では使用しません。

## 終了操作の用語とキー設計

表示領域の終了と編集対象の削除を明確に区別し、キーバインドの動詞も分離しています。

- close (動詞 `c`)
  - ウィンドウまたはタブ (表示領域) を閉じる
  - 参照先のバッファは削除せず、メモリ上に保持する
  - 例: `<leader>cw` (現在のウィンドウを閉じる)、`<leader>cW` (他のウィンドウを閉じる)、`<leader>ct` (現在のタブを閉じる)
- delete (動詞 `d`)
  - バッファ (編集対象) をアンロードし、バッファリストから外す
  - ウィンドウの分割レイアウトを崩さずに閉じるため、内部的には `Snacks.bufdelete` を使用する
  - 例: `<leader>db` (現在のバッファを削除する)

## 表示方針

画面上部の bufferline には、`bufferline.nvim` の `mode = "tabs"` を指定して Neovim のタブを表示します。
プラグイン名に bufferline とありますが、表示対象はバッファではなくタブです。

バッファの一覧は画面上部に常時並べず、必要に応じて buffer picker (`sb`) や前後のバッファ移動 (`[b` / `]b`) で切り替えます。
タブは作業スペース (ウィンドウ配置) の切り替え単位として扱い、ファイルごとに 1 タブ作成するような運用は想定しません。
画面下部の lualine には、現在のタブ番号と総タブ数を `n/N` の形式で表示します。

## 操作方針

バッファ、ウィンドウ、タブのライフサイクル操作 (生成・終了) は、`<leader>` から始まる `動詞 + 目的語` のキー体系に割り当てます。

- 生成 (new): 動詞 `n` (`<leader>nb`、`<leader>nt`、`<leader>nwh`、`<leader>nwv`)
  - `<leader>nt` でタブを作成した際は、そのタブに Alpha のダッシュボードを表示します。
- 終了 (close / delete): 表示領域のクローズには `c` (`<leader>cw`、`<leader>ct`)、バッファの削除には `d` (`<leader>db`)
- 移動: 同種の対象間の前後移動には `[` と `]`、ウィンドウ間の方向移動には `<C-h/j/k/l>` および `<leader>gwh/j/k/l`

具体的な割り当ては [Neovim キーバインド設計](./keybinds.md) で管理します。
